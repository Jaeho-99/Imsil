# 지시문 — 34개소 검증셋 문장 감성 판정

이 파일을 받은 Claude는 **판정자**입니다. 34개소 분석에서 ChatGPT 웹 UI가 했던 일을 같은 프롬프트와 같은 묶음으로 다시 합니다.
사람이 이 결과를 34개소 사람 라벨로 채점해, 판정 도구를 바꿔도 품질이 같은지 확인합니다. 그래서 아래 규칙을 어기면 검증 자체가 무효가 됩니다.

사용자가 이번이 `run1`인지 `run2`인지 알려 줍니다. 아래의 `{run}`을 그 값으로 바꿔 읽으세요.

## 규칙

1. **아래 '읽는 파일'만 엽니다.** 그 밖의 파일은 열거나 검색하지 않습니다. 특히 사람 라벨과 이전 판정이 들어 있는 곳은 보지 않습니다.
   - `output/sentiment/` (단, `output/sentiment/llm_labeling/chunks/`는 읽는 파일입니다)
   - `input/sentiment/llm_labeling/llm_runs/`
   - `input/new_sites/sentiment/`와 `output/new_sites/sentiment/`의 다른 run 폴더와 채점 결과
2. **판정은 직접 문장을 읽고 합니다.** 사전·키워드·규칙으로 라벨을 붙이는 코드를 만들지 않고, API나 다른 모델을 부르지 않습니다.
3. **프롬프트를 고치거나 기준을 더하지 않습니다.** 프롬프트에 없는 기준이 필요해 보이면 가장 가까운 규칙을 적용하고 라벨 뒤에 `?`를 붙입니다.
4. **run2는 run1과 다른 새 대화에서 합니다.** run1의 결과 파일을 열지 않습니다.
5. 채점(`sentiment.py validate`)은 실행하지 않습니다. 채점은 사람이 두 run을 모두 끝낸 뒤에 합니다.

## 읽는 파일

| 파일 | 쓰임 |
|---|---|
| `input/sentiment/llm_labeling/프롬프트_v1.md` | 판정 기준. `<<<PROMPT_START>>>`부터 `<<<PROMPT_END>>>`까지가 지시 전부입니다. 마지막 줄의 "준비됨" 응답과 "다음 메시지부터 묶음을 보내겠다"는 웹 대화용 안내이므로 건너뜁니다 |
| `output/sentiment/llm_labeling/chunks/*.txt` | 판정할 묶음 12개 (`본_01`~`본_08`, `보강_01`~`보강_04`, 모두 548문장) |

## 하는 일

1. 프롬프트를 읽습니다.
2. 묶음 파일을 이름 순서대로 하나씩 읽고 판정합니다. 한 묶음을 다 판정한 뒤 다음 묶음으로 넘어갑니다.
3. 묶음마다 결과를 `input/new_sites/sentiment/검증_34개소/{run}/{묶음 이름}.tsv`에 씁니다 (예: `run1/본_01.tsv`).
   - 프롬프트의 '출력 형식' 그대로, 한 줄에 `unit_id<TAB>label` 하나입니다. 헤더·설명·코드블록을 넣지 않습니다.
   - 묶음에 있는 모든 `unit_id`를 입력 순서 그대로 씁니다. label은 `긍정`·`부정`·`중립`·`혼합` 중 하나이고, 확신이 없으면 뒤에 `?`를 붙입니다.
   - 파일은 UTF-8로 저장합니다.
4. 12개를 다 쓰면 `python src/new_sites/sentiment.py check`를 실행합니다. '34개소 검증셋 {run}' 줄에 누락·형식 오류가 있으면 그 묶음을 다시 읽고 고칩니다. 이 명령은 사람 라벨을 읽지 않습니다.
5. 같은 폴더에 `실행기록.md`를 씁니다.

```markdown
- 도구: Claude Code
- 모델: (지금 대화의 모델 이름. 사용자가 /model 로 확인해 고칠 수 있습니다)
- 날짜: YYYY-MM-DD
- 프롬프트: input/sentiment/llm_labeling/프롬프트_v1.md (수정 없음)
- 대화: 이 run 만 한 새 대화
- 묶음: output/sentiment/llm_labeling/chunks/ 12개, 548문장
- temperature: 고정하지 않음 (2회 실행 불일치율로 변동성 보고)
```

6. 사용자에게 끝났다고 알리고, check 결과(누락 0 등)를 한 줄로 전합니다.
