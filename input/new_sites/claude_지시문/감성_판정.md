# 지시문 — 추가 관광지 문장 감성 판정

이 파일을 받은 Claude는 **판정자**입니다. 추가 관광지 2개소(성수산, 오수의견국민여가캠핑장) 리뷰 문장의 감성을 34개소 분석과 같은 프롬프트로 판정합니다.
같은 판정을 서로 다른 대화에서 두 번(run1, run2) 하고, 두 결과의 불일치율로 판정의 변동성을 보고합니다. 그래서 두 run은 서로를 보지 않아야 합니다.

사용자가 이번이 `run1`인지 `run2`인지 알려 줍니다. 아래의 `{run}`을 그 값으로 바꿔 읽으세요.

## 규칙

1. **아래 '읽는 파일'만 엽니다.** 그 밖의 파일은 열거나 검색하지 않습니다. 특히 아래는 보지 않습니다.
   - `input/new_sites/sentiment/runs/`의 다른 run 폴더
   - `output/new_sites/sentiment/`의 `chunks/` 밖 파일 (문장 라벨·집계·검토표가 들어 있습니다)
   - 34개소 감성 결과 (`output/sentiment/`, `input/sentiment/llm_labeling/llm_runs/`)
2. **판정은 직접 문장을 읽고 합니다.** 사전·키워드·규칙으로 라벨을 붙이는 코드를 만들지 않고, API나 다른 모델을 부르지 않습니다.
3. **프롬프트를 고치거나 기준을 더하지 않습니다.** 프롬프트에 없는 기준이 필요해 보이면 가장 가까운 규칙을 적용하고 라벨 뒤에 `?`를 붙입니다.
4. **run2는 run1과 다른 새 대화에서 합니다.** run1의 결과 파일을 열지 않습니다.

## 읽는 파일

| 파일 | 쓰임 |
|---|---|
| `input/sentiment/llm_labeling/프롬프트_v1.md` | 판정 기준. `<<<PROMPT_START>>>`부터 `<<<PROMPT_END>>>`까지가 지시 전부입니다. 마지막 줄의 "준비됨" 응답과 "다음 메시지부터 묶음을 보내겠다"는 웹 대화용 안내이므로 건너뜁니다 |
| `output/new_sites/sentiment/chunks/추가_*.txt` | 판정할 묶음. 묶음마다 150문장 안팎이고 첫 줄에 문장 수가 적혀 있습니다 |

## 하는 일

1. 프롬프트를 읽습니다.
2. 묶음 파일을 이름 순서대로 하나씩 읽고 판정합니다. 한 묶음을 다 판정한 뒤 다음 묶음으로 넘어갑니다.
3. 묶음마다 결과를 `input/new_sites/sentiment/runs/{run}/{묶음 이름}.tsv`에 씁니다 (예: `run1/추가_01.tsv`).
   - 프롬프트의 '출력 형식' 그대로, 한 줄에 `unit_id<TAB>label` 하나입니다. 헤더·설명·코드블록을 넣지 않습니다.
   - 묶음에 있는 모든 `unit_id`를 입력 순서 그대로 씁니다. 행 수가 묶음 첫 줄의 문장 수와 같아야 합니다.
   - label은 `긍정`·`부정`·`중립`·`혼합` 중 하나이고, 확신이 없으면 뒤에 `?`를 붙입니다.
   - 파일은 UTF-8로 저장합니다.
4. 묶음을 다 쓰면 `python src/new_sites/sentiment.py check`를 실행합니다. '추가 관광지 {run}' 줄에 누락·형식 오류·덜 된 묶음이 있으면 그 묶음을 다시 읽고 고칩니다.
5. 같은 폴더에 `실행기록.md`를 씁니다.

```markdown
- 도구: Claude Code
- 모델: (지금 대화의 모델 이름. 사용자가 /model 로 확인해 고칠 수 있습니다)
- 날짜: YYYY-MM-DD
- 프롬프트: input/sentiment/llm_labeling/프롬프트_v1.md (수정 없음)
- 대화: 이 run 만 한 새 대화
- 묶음: output/new_sites/sentiment/chunks/ N개, M문장
- temperature: 고정하지 않음 (2회 실행 불일치율로 변동성 보고)
```

6. 사용자에게 끝났다고 알리고, check 결과(누락 0, run1·run2가 모두 있으면 불일치율)를 한 줄로 전합니다.
