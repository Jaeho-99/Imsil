## 과제
문장 하나마다 라벨 하나를 매깁니다. 라벨은 다음 셋 중 하나입니다.
긍정 / 부정 / 중립

## 판정 순서 — 위에서부터 차례로 적용합니다

1. **평가어가 있는가**
   없으면 → 중립. 여기서 멈춥니다. 작성자의 속마음을 추론하지 마십시오.

2. **평가의 방향은**
   좋다는 쪽 → 긍정. 나쁘다는 쪽 → 부정.
   강도는 보지 않습니다. "조금 아쉽네요"도 부정입니다.

3. **판단이 서지 않으면**
   가장 가까운 규칙을 적용하고, 그 문장의 label 뒤에 `?`를 붙입니다. (예: `중립?`)
   임의로 새 기준을 만들지 마십시오.

## 경계 사례 사전 — 이미 결정된 사항입니다. 다시 고민하지 마십시오

| 유형 | 판정 | 근거 |
|---|---|---|
| 헛걸음 / 문 닫아서 못 들어감 | **부정** | 본인의 좌절된 방문 경험이 서술되어 있음. 운영·안내의 실패는 개선 대상 |
| 개선 요구 ("−면 좋겠다") | **부정** | 판별 질문: 지금 없는 것을 요구하고 있는가. 결핍이 텍스트에 쓰여 있으므로 추론이 아님 |
| └ 재방문 의사 ("봄에 다시 오겠음") | 긍정 | |
| └ 관광지 평가가 아닌 소망 ("많이 놀러오시길") | 중립 | |
| 이중부정 ("나쁘지 않아요", "부족함이 없어요") | **의미대로** | 부정 단어가 있어도 문장의 뜻이 긍정이면 긍정. 단어가 아니라 문장을 읽습니다 |
| 운영 정보만 ("월요일은 쉬어요") | **중립** | 본인 경험이 아니라 정보 전달. 헛걸음과의 차이는 좌절된 방문이 서술되었는가 |
| 사실 + 평가 ("입장료 3000원이지만 돈이 아깝지 않았어요") | **평가 쪽** (→긍정) | 가격이 언급됐는지가 아니라 평가가 붙었는지를 봅니다. "입장료가 비싸요"는 부정 |
| 약한 부정 ("그린이 조금 아쉽네요") | **부정** | 3분류는 방향만 봅니다. 강도로 나누지 않습니다 |
| 내용 없음 ("붕어섬출렁다리", "따뜻한 아메리카노가") | **중립** | 장소명·조각 문장. 자주 나옵니다. 버리지 말고 중립을 매기십시오 |
| 전언·인용 ("그렇게 맛있다고해서 먹어봄") | **중립** | 남의 평가이고 본인 평가가 없음 |
| 외국어 리뷰 | **동일 기준** | 한국어와 같은 규칙을 적용합니다 |

## 한 문장 안에 긍정과 부정이 둘 다 있을 때
문장을 쪼개지 마십시오. 명시적 긍정과 명시적 부정이 **둘 다** 뚜렷하게 있는 경우에만
label 자리에 `혼합`이라고 쓰십시오.
"-지만/-으나"가 있다는 이유만으로는 혼합이 아닙니다. 한쪽이 사실 진술이면 혼합이 아닙니다.
(예: "여러번 방문이지만 매번 좋았습니다" → 긍정)

## 입력 형식
`unit_id | sent_no/n_sent | 관광지 | 플랫폼 | 문장`

같은 리뷰에서 나온 문장들은 연달아 있습니다. `sent_no/n_sent`로 그 리뷰의 몇 번째 문장인지
알 수 있습니다. **앞뒤 문장을 문맥으로 참고하되, 라벨은 그 문장 하나에 대해서만 매깁니다.**

## 출력 형식 — 반드시 이것만
탭으로 구분된 두 열. 헤더 없음. 설명·인사말·요약·코드블록 없이 **표만** 출력합니다.

```
unit_id<TAB>label
```

- 입력에 있는 **모든** unit_id를 **입력 순서 그대로** 출력합니다. 빠뜨리거나 순서를 바꾸지 마십시오.
- label은 `긍정` `부정` `중립` `혼합` 중 하나이며, 확신이 없으면 뒤에 `?`를 붙입니다.
- 문장을 다시 적지 마십시오. unit_id와 label만 출력합니다.
- 개수를 세어 입력 문장 수와 출력 행 수가 같은지 확인한 뒤 출력하십시오.

## 실행 절차

1. **새 대화**를 연다. 위 프롬프트를 통째로 붙여넣는다. ("준비됨" 응답 확인)
2. `input/` 의 묶음 파일을 **1번부터 순서대로** 한 번에 하나씩 붙여넣는다.
3. 응답을 `output/run1/` 에 같은 파일명 `.tsv` 로 저장한다.
4. 전부 끝나면 **완전히 새 대화**를 열어 1~3을 반복하고 `output/run2/` 에 저장한다.
   (3강에서 정한 "2회 실행 불일치율 보고"용. 같은 대화에서 두 번 돌리면 앞 답을 보고 답하므로 무효다.)

## 반드시 기록할 것 — 재현성 (3강 확정 사항)

`output/실행기록.md` 에 다음을 적는다. 없으면 보고서에 방법을 쓸 수 없다.

- 모델명과 **버전** (예: GPT-5.x, 화면 하단/설정에 표시되는 정확한 표기)
- 실행 날짜
- 프롬프트 버전 (이 파일: `프롬프트_v1.md`)
- 웹 UI로 돌렸는지 API로 돌렸는지
- (API면) temperature 값 — **0으로 고정**

> **웹 UI의 한계**: temperature를 0으로 고정할 수 없다.
> 3강에서 정한 재현성 요건 중 "temperature 0"을 못 지키는 것이므로,
> 웹 UI로 돌렸다면 보고서에 **"temperature 미고정, 2회 실행 불일치율로 변동성을 보고"** 라고 명시한다.
> 숨기지 말고 그대로 쓴다. 불일치율을 보고하는 이유가 바로 이것이다.
