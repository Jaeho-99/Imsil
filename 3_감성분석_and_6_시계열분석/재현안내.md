# 재현 안내 — 코드 실행 순서와 입력·출력

분석 결과를 다시 산출하려는 경우의 실행 안내입니다.
분석의 내용과 결과 해석은 `README.md`를 참고하십시오.

## 1. 환경 준비

Python 3.11 이상 (개발·검증 환경은 3.14, Windows 11)

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

macOS · Linux에서는 `.venv/bin/python`으로 바꿔 읽으십시오.
실제 검증은 Windows에서만 수행했습니다.

> **한글 폰트 안내** — 그래프는 맑은 고딕(`Malgun Gothic`)을 사용합니다.
> 이 폰트가 없는 환경에서는 PNG 그래프의 한글이 깨져 보일 수 있으나,
> **CSV 산출물의 수치에는 영향이 없습니다.** 표의 수치를 기준으로 확인하시고,
> 그래프가 필요하면 각 스크립트의 `setup_matplotlib_font()` 에서 폰트 이름을
> 해당 환경에 설치된 한글 폰트로 바꾸어 실행하십시오.

### torch · transformers는 설치하지 않아도 됩니다

이 두 패키지는 후보 방법 ②(공개 사전학습 모델 `daekeun-ml/koelectra-small-v3-nsmc`)의
성능 검증에만 사용했고, 이 방법은 비교에서 채택되지 않았습니다(최종 채택은 ③ LLM).

사용하는 스크립트는 아래 3개뿐이며, **최종 결과 재현에는 관여하지 않습니다.**

```
분석/감성분석/pilot/model2_smoke.py
분석/감성분석/calibration/decide_threshold.py
분석/감성분석/evaluation/run_model2.py
```

②번 검증을 다시 수행할 때만 `pip install torch transformers`를 추가하십시오.

## 2. 폴더 구조를 유지해 주십시오

분석 스크립트는 자기 위치를 기준으로 상위 2단계를 프로젝트 최상위로 계산하고,
거기서부터 데이터 경로를 찾습니다.

```python
BASE_DIR     = 스크립트가 있는 폴더
PROJECT_ROOT = BASE_DIR/../..
INPUT_CSV    = PROJECT_ROOT/data/임실군_관광지_리뷰데이터.csv
```

또한 시계열 분석 중 감성 관련 3개 스크립트는 감성분석 산출물을 직접 참조합니다.

```python
PROJECT_ROOT/분석/감성분석/fullscale-final/전수_문장라벨_최종.csv
```

따라서 **`data/`, `분석/감성분석/`, `분석/시계열분석/`의
폴더명과 계층을 바꾸면 실행이 중단됩니다.** 구조를 평탄화하는 경우도 마찬가지입니다.

다른 위치로 옮기실 경우, 각 스크립트 상단의 경로 상수(20~40행 부근)만
수정하면 됩니다. 절대경로는 코드 어디에도 없습니다.

## 4. 감성 분석 실행 (보고서 3장)

작업 폴더: `분석/감성분석/`

### 4.1 전 과정 자동 실행은 불가능합니다

최종 채택한 감성분류 방법(③ LLM)은 **문장 묶음을 LLM에 입력하고 판정 결과를
받아 저장하는 수동 단계**를 포함합니다. 따라서 감성분석은 명령 한 번으로
전 과정이 재실행되지 않습니다.

코드가 담당하는 부분은 다음과 같습니다.

```
[코드]  입력 묶음 생성      build_chunks.py / build_fullscale.py
[수동]  LLM 판정 후 결과 저장  output/run1/ · output/run2/ 등에 저장
[코드]  채점 · 병합 · 집계    run_llm3.py / merge_fullscale.py / merge_final.py
```

**최종 결과물은 이미 산출되어 `fullscale-final/`에 포함되어 있습니다.**
결과 확인이 목적이라면 해당 폴더의 CSV를 사용하십시오.

다만 마지막 단계인 `mixed-final-review/merge_final.py`는 LLM 판정 없이 단독 실행이
가능합니다. 판정이 어려운 문장 267건의 확정 자료와 직전 단계 문장 라벨을 결합해
`fullscale-final/` 5개 파일을 다시 만듭니다.

```bash
python 분석/감성분석/mixed-final-review/merge_final.py
```

2026-09-01 이 제출본에서 실행하여 **CSV 5개가 기존 최종본과 완전히 동일하게
재생성됨**을 확인했습니다.

### 4.2 재실행하면 안 되는 스크립트 — 확정 자료 덮어쓰기

아래 세 스크립트는 모두 **`mixed-final-review/혼합227_최종검토용.xlsx`를 덮어씁니다.**
이 파일에는 판정이 어려운 문장 267건에 대한 **연구자의 최종 판정이 들어 있고**,
`merge_final.py`가 이를 읽어 최종 라벨을 만듭니다.

| 스크립트 | 하는 일 | 덮어쓰는 파일 |
|---|---|---|
| `mixed-final-review/build_final_review.py` | 227건 검토표를 새로 생성 | `혼합227_최종검토용.xlsx` (+ `혼합227_대상.csv`, `gpt_초벌_양식.csv`) |
| `mixed-final-review/apply_gpt_draft.py` | LLM 초벌 판정을 검토표에 반영 | `혼합227_최종검토용.xlsx` |
| `mixed-final-review/relayout_review.py` | 검토표 서식 조정 | `혼합227_최종검토용.xlsx` |

> ### 확정 자료가 들어 있는 상태에서는 이 세 개를 실행하지 마십시오
>
> 실행하면 판정이 비어 있는 검토표로 덮어써지고, 그 뒤 `merge_final.py`를 돌리면
> **오류 없이 종료코드 0으로 끝나면서 아무 결과도 만들지 않습니다.**
> 콘솔에 오류가 나지 않으므로 알아채기 어렵습니다.
>
> 감사 중 41개 스크립트를 알파벳순으로 일괄 실행했을 때 실제로 이 현상이 발생했습니다.
> 세 스크립트는 267건 확정 **절차의 기록**으로 포함한 것이며, 재현을 위해 실행할
> 필요가 없습니다. 확정 결과는 `혼합227_최종검토용.xlsx`에 이미 담겨 있습니다.

### 4.3 검증셋 생성 코드에 대하여 — 재실행하지 마십시오

`labeling/build_labeling_set.py`는 사람 검증 자료(본 검증셋 · 부정 보강셋)를
처음 만들 때 사용한 코드입니다. **당시의 생성 절차를 보존하기 위해 포함한 기록 코드이며,
지금 다시 실행해 기존 검증셋을 재생성하는 용도가 아닙니다.**

문장 분리 규칙(`textsplit.py`)이 검증셋을 만든 뒤에 한 차례 수정되었기 때문입니다.
현재 규칙은 내용이 없는 조각을 앞 문장에 도로 붙입니다(해당 파일 첫머리 설명 참조).
그 결과 지금 실행하면 다음과 같이 달라집니다.

| | 보존본 (검증셋 생성 당시) | 지금 실행할 경우 |
|---|---|---|
| 문장 수 | **539** | **533** |
| `unit_id` 체계 | `MAIN-0001` ~ `MAIN-0539` | 6개가 병합되어 이후 번호가 밀림 |

**사람이 판정한 확정 라벨은 539문장 체계의 `unit_id`를 기준으로 작성되어 있습니다.**
따라서 재생성본으로 덮어쓰면 확정 라벨이 다른 문장에 연결되어 정합성이 깨집니다.
실제로 확정 라벨 532건 중 6건은 재생성본에 존재하지 않는 `unit_id`입니다.

> **검증 자료는 제출본의 보존본을 그대로 사용하십시오.**
>
> | 자료 | 위치 |
> |---|---|
> | 라벨링용 원본 (539문장) | `분석/감성분석/labeling/검증셋_본_라벨링용.csv` · `.xlsx` |
> | 부정 보강셋 | `분석/감성분석/labeling/검증셋_부정보강_라벨링용.csv` · `.xlsx` |
> | **사람 확정 라벨 (532문장)** | `분석/감성분석/labeling/확정/검증셋_본_확정.csv` |
> | 부정 보강 확정 라벨 (166문장) | `분석/감성분석/labeling/확정/검증셋_보강_확정.csv` |
> | 제외 목록 | `분석/감성분석/labeling/확정/제외목록.csv` |
>
> 보고서에 수록된 성능 수치(macro-F1 0.906 등)는 모두 위 확정 라벨에서 산출되었습니다.

같은 폴더의 `build_relabel.py` · `finalize.py` · `kappa.py`는 확정 라벨을 입력으로

## 5. 실행 결과 확인 방법

각 스크립트는 결과를 저장하기 전에 자체 검사를 수행하고, **검사 항목과
결과를 콘솔에 모두 출력**합니다.

```
 1. 원본 리뷰 데이터 존재 확인: [PASS]
 2. 최종 감성 데이터 존재 확인: [PASS]
 ...
```

검사에 실패하면 그 자리에서 실행이 중단되고 어긋난 항목이 표시됩니다.
따라서 **콘솔 출력만 확인하시면 정상 여부를 판단할 수 있습니다.**

검사 항목 수는 결합하는 자료가 많을수록 늘어납니다.

| 스크립트 | 검사 항목 수 |
|---|---|
| `timeseries_input_audit.py` (T-1) | 8 |
| `tierA_seasonal_review_analysis.py` (T-2) | 10 |
| `tierA_seasonal_sentiment_analysis.py` (T-3) | 14 |
| `cheese_festival_window_setup.py` (T-4) | 15 |
| `cheese_festival_review_analysis.py` (T-5) | 16 |
| `cheese_festival_sentiment_analysis.py` (T-6) | 20 |
| `timeseries_integration_check.py` (T-8) | 27 |

### 검증 기록 (2026-09-01)

이 제출본의 폴더 구성에서 3.1의 5개 스크립트를 순서대로 재실행하여
**87개 검사 항목 전부 통과**를 확인했습니다.
3.3의 점검용 스크립트 2종도 함께 실행하여 모두 통과했습니다.

재생성된 산출 CSV를 보고서 작성 시점의 결과와 MD5로 대조한 결과,
**보고서 수치가 담긴 19개 파일이 모두 완전히 동일**했습니다.
계절별 리뷰 수·감성 분포, 축제 전·중·후 비교, 축제 구간 표가 모두 여기에 포함됩니다.

차이가 있는 파일은 점검용 산출물인 `timeseries_input_inventory.csv` 하나이며,
이 자료의 범위에 포함되지 않는 키워드 전처리 데이터를 점검 대상에서 제외하여
행이 3행에서 2행으로 줄고 파일 경로 기록이 갱신된 것입니다.
보고서 수치와는 무관합니다.
