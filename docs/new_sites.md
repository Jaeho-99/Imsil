# 추가 관광지 2개소 온라인 리뷰 분석

전북연구원·임실군청 추가 요청(2026-10-30 안내) 중 **2. 추가 관광지 2개소 온라인 리뷰 데이터 분석**의 코드와 데이터입니다.
코드는 `src/new_sites/`, 사람이 만든 입력은 `input/new_sites/`, 결과는 `output/new_sites/`에 있습니다.

| 항목 | 내용 |
|---|---|
| 분석 대상 | 성수산, 오수의견국민여가캠핑장 |
| 플랫폼 | 네이버 플레이스만 (구글 지도에는 두 곳의 리뷰가 없어 수집하지 않음, 2026-11-05 결정) |
| 수집 기간 | 2022-01-01 ~ 2026-11-02 (`config.py`의 `DATE_END`로 고정) |
| 분석 | 키워드(빈도·TF-IDF·n-gram) · 연관관계(연관규칙·동시출현 네트워크) · 문장 단위 감성 · 만족·불만 요인 |
| 최종 제출 | 2026-11-14 |

34개소 분석 코드를 **고치지 않고 불러 쓰는 것**을 원칙으로 했습니다. 두 분석의 결과를 같은 기준으로 나란히 놓기 위해서입니다.
설정(대상·기간·불용어·경로)은 모두 [`src/new_sites/config.py`](../src/new_sites/config.py) 한 곳에 있습니다.

| 단계 | 스크립트 (`src/new_sites/`) | 34개소에서 가져온 것 | 새로 만든 것 |

| 전처리 | `preprocess.py` | 1차전처리 규칙 | 규칙을 코드로 역산 (아래 검증 참고), 번역 |

| 요약 | `summary.py` | | 보고서용 표·문장 재료 |

## 실행 순서

명령은 모두 **레포 최상위에서** 실행합니다. 설치는 [README](../README.md#준비)를 따릅니다.
`kiwipiepy==0.23.2`는 꼭 이 버전으로 설치합니다. 34개소 노트북과 버전이 다르면 형태소 분석 결과가 달라집니다.

### 1. 수집 (네이버에 접속되는 PC에서)

장소 ID는 `config.py`의 `naver_place_id`에 넣어 두었습니다 (성수산 13491702, 오수의견국민여가캠핑장 2006533162).

```bash
python src/new_sites/collect_naver.py
```

결과는 34개소 수집과 같은 `output/collect/naver/`에 쌓입니다 (`{관광지명}_naver_reviews.csv`, `{ID}_raw.json`, `{관광지명}_수집정보.json`). 작성자 닉네임이 들어 있어 git에는 올라가지 않습니다.

네이버 수집기가 캡차·405로 막히면 몇 시간 뒤 같은 명령을 다시 실행합니다. 받은 데까지 `{ID}_raw.json`에 남아 있어 이어받습니다(`retry_naver.py`는 이것을 몇 시간 간격으로 대신 해 줍니다). 계속 막히면 브라우저에서 리뷰 탭을 직접 끝까지 넘겨 본 뒤, 개발자도구 Network 탭에서 HAR(sanitized)로 내보내고 합칩니다. HAR 파일은 레포에 넣지 않고 내 PC에 둡니다.

```bash
python src/new_sites/import_har.py 다운로드\m.place.naver.com.har
```

수집이 끝나면 `config.py`의 `DATE_END`를 수집일 전날로 고정합니다. 이번에는 첫 수집일(2026-11-03)의 전날인 2026-11-02로 정했습니다.

### 2. 분석

```bash
python src/new_sites/run_all.py            # 전 과정 (API 단계 포함)
python src/new_sites/run_all.py --no-api   # API 없이 돌릴 수 있는 단계만
```

단계별로 돌릴 때는 아래 순서입니다. 각 스크립트는 저장 전에 `[PASS]/[WARN]/[FAIL]` 자체 검사를 출력하고, `FAIL`이면 그 자리에서 멈춥니다.

| 순서 | 명령 (`python src/new_sites/…`) | API | 출력 (`output/new_sites/…`) · 비고 |
|---|---|:-:|---|
| 1 | `build_dataset.py` | | `추가관광지_리뷰데이터.csv` |
| 2 | `preprocess.py --translate` | ○ | `추가관광지_리뷰데이터_1차전처리.csv`. 외국어 리뷰만 번역. 실명 후보 목록을 확인해 `input/new_sites/비식별_치환목록.csv`에 적고 1번부터 다시 실행 |
| 3 | `keywords.py` | | `keyword/` |
| 4 | `association.py` | ○ | `association/`. 키워드 정규화에 API를 쓴다. `--no-llm`이면 API 없이 |
| 5 | `sentiment.py build` | | `sentiment/문장목록.csv`, `sentiment/chunks/` |
| 6 | `sentiment.py validate --run run1` (run2도) | ○ | `sentiment/검증_34개소/`. 34개소 사람 검증셋 548문장 재채점 |
| 7 | `sentiment.py run --run run1` (run2도) | ○ | `sentiment/runs/`. 독립 2회 실행 |
| 8 | `sentiment.py review` | | `sentiment/사람검토표.xlsx` 양식 생성 → `input/new_sites/사람검토표.xlsx`로 복사해 **사람이 채움** |
| 9 | `sentiment.py merge` | | `sentiment/` 최종 문장·리뷰 라벨, 관광지별 집계, 그림 |
| 10 | `satisfaction.py` | ○ | `satisfaction/`. 중단되면 다시 실행. 끝난 리뷰는 건너뜀 |
| 11 | `summary.py` | | `summary/분석결과_요약.md`, `산출물_목록.csv` |

**사람이 해야 하는 일은 두 가지**입니다. 실명 후보 확인(2번)과 감성 검토표 작성(8번)입니다. 검토표의 `1_혼합확정` 시트는 모델이 `혼합`이나 `?`로 낸 문장을 34개소 267건 확정과 같은 기준으로 판정하고, `2_블라인드검증` 시트는 모델 라벨을 가린 무작위 100문장에 사람 라벨을 적습니다. 코드는 `input/`의 채운 검토표를 덮어쓰지 않습니다.

리뷰가 바뀐 뒤 `build`를 다시 하면 묶음 구성과 `unit_id`가 달라집니다. 이때 이전 run 결과·검토표 양식·최종 라벨은 `.local/new_sites_감성_이전실행/{시각}/`으로 옮겨지고(지우지 않음), `merge`는 채운 검토표의 문장이 지금 문장목록과 다르면 멈춥니다. 가명 ID는 `output/collect/naver/추가관광지_리뷰ID_대응표.csv`에 남아 있어 다시 돌려도 바뀌지 않습니다.

## 34개소 결과와 맞춰 본 기록 (2026-11-02)

새 코드가 34개소 때와 같은 계산을 하는지 34개소 데이터로 확인했습니다.

| 확인 | 결과 |
|---|---|
| 1차전처리 규칙 (`preprocess.py`) | 외국어를 뺀 5,206건에서 34개소 1차전처리본과 99.98% 일치 (공백 차이 제외, 1건 다름) |
| 키워드 토큰 (`keywords.py --check-base`) | Kiwi 0.23.2에서 5,267행 중 99.94% 일치 (3행 다름). 0.24.1은 86.7%, 0.22.2는 94.0% |
| 감성 채점 (`sentiment.py validate --score-only`) | 34개소 ChatGPT 출력을 넣으면 macro-F1 0.906 · 부정 재현율 0.910 · 불일치 4.20% · κ 0.936으로 보고서 수치와 같음 |

## 수집 기록

| 관광지 | 플랫폼 | 수집 | 방법 |
|---|---|---|---|
| 성수산 | 네이버 | 2/2건 (2026-11-03) | 수집기 |
| 오수의견국민여가캠핑장 | 네이버 | 237/238건 (2026-11-03~04) | 수집기 100건 + 브라우저 기록(HAR) 188건, 겹친 51건 제외 |

- 네이버가 2026-11부터 자동 요청에 캡차(사람 확인)를 요구해, 캠핑장은 수집기로 100건을 받은 뒤 막혔습니다. 나머지는 사람이 브라우저에서 리뷰를 끝까지 넘겨 본 기록(HAR)에서 꺼냈습니다 (`import_har.py`). 응답 형식이 같아 CSV 컬럼과 값도 같습니다.
- 238건 중 빠진 1건은 두 수집 사이에 새로 올라온 리뷰로 보입니다. 합친 237건의 작성일이 모두 2026-11-02 이전이고, 수집기로 받을 때의 전체 수가 237건이었습니다. `DATE_END`(2026-11-02) 밖이라 분석 대상에 들지 않습니다.
- 캠핑장 네이버 리뷰 237건의 작성일은 2025-07-21 ~ 2026-11-02입니다 (2025년 124건, 2026년 113건).
- 구글 지도에는 두 곳의 리뷰가 없어 수집하지 않았습니다. `output/collect/google/`에 같은 이름의 구글 수집 파일이 있으면 `build_dataset.py`가 함께 읽도록 코드는 남겨 두었습니다.

## 34개소와 다른 점 (보고서 방법론에 밝힐 것)

- **플랫폼**: 34개소는 구글·네이버 두 플랫폼, 추가 2개소는 네이버만입니다. 플랫폼별 비교는 34개소의 네이버 리뷰와 놓아야 같은 조건입니다.
- **감성 분류 실행 경로**: 34개소는 ChatGPT 웹 UI에 프롬프트 v1을 붙여넣었고, 지금 코드는 같은 프롬프트를 Anthropic API(`config.SENT_MODEL`)로 실행합니다. 묶음마다 새 요청을 보내므로 앞 묶음의 답이 뒤로 새지 않습니다. 모델이 달라진 만큼 `validate`로 34개소 사람 검증셋을 이 모델로 다시 채점해 34개소(0.906)와 나란히 보고합니다.
- **temperature**: 현재 모델은 temperature를 받지 않습니다. 34개소와 같이 독립 2회 실행의 불일치율로 변동성을 보고합니다. 모델명·실행 일시·응답 모델 ID·프롬프트 해시는 `output/new_sites/sentiment/runs/run*/실행기록.json`에 남습니다.
- **TF-IDF**: 2개소만으로는 IDF가 의미가 없어 34개소의 21개소 문서에 더해 23개 문서로 계산합니다.
- **연관규칙**: 관광지 단위 규칙을 내기 위해 `--min-place-transactions`를 20으로 낮췄습니다 (스크립트 기본 100, 34개소 보고서 결과는 50). 나머지 임계값은 같습니다.

## 확인이 필요한 사항

- **성수산의 범위**: 34개소에 이미 `성수산왕의숲자연휴양림`(리뷰 21건)이 있습니다. 이번 대상이 산 자체(등산로, 상이암 포함 여부)인지 휴양림과 같은 곳인지 교수님께 확인이 필요합니다. 지금은 네이버의 '성수산' 장소를 새로 수집하고, 휴양림은 비교 대상으로만 둡니다 (`config.COMPARE_PLACES`).
- **네이버 날짜 필드**: 작성일(`created`)을 씁니다. 34개소 통합 데이터를 만들 때 어느 필드를 썼는지는 코드가 남아 있지 않아 확인하지 못했습니다.
