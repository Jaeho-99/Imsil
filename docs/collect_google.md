# 구글 지도 리뷰 수집기

임실군 관광지 리뷰 빅데이터 분석용 구글 지도(Google Maps) 리뷰 수집 스크립트입니다.
Playwright로 실제 크롬을 띄워 장소 페이지의 리뷰 탭을 열고, 구글이 내부적으로 주고받는
리뷰 목록 응답(batchexecute RPC)을 가로채 CSV / XLSX로 저장합니다.

---

## 1. 폴더 구성

> 2026-11-05 레포 정리로 위치가 바뀌었습니다. 명령은 모두 **레포 최상위에서** 실행합니다.

```
레포 최상위/
├─ requirements-google.txt          ← 파이썬 패키지 목록 (수집기 전용)
├─ docs/collect_google.md           ← 지금 읽고 있는 문서
├─ src/collect/
│  ├─ google_reviews.py             ← 실행 파일 (브라우저 조작 + 수집 본체)
│  ├─ gmaps_rpc.py                  ← 구글 RPC 응답 파서 (네트워크를 타지 않는 순수 함수)
│  ├─ test_google_extractors.py     ← 구글 접속 없이 파싱 로직만 검증하는 자체 테스트
│  └─ google_login.py               ← 처음 한 번만 실행하는 준비 스크립트 (4절 참고)
├─ output/collect/google/           ← 실행 결과 (작성자 정보 포함 → git 제외)
└─ .local/                          ← 로그인 프로필·진단 스냅샷 (내 PC 에만, git 제외)
   ├─ chrome_profile_google/
   └─ diagnostics/
```

세 파일의 역할 분담:

| 파일 | 하는 일 | 구글 접속 |
|---|---|---|
| `google_reviews.py` | 크롬 실행 → 장소 진입 → 리뷰 탭 열기 → 최신순 정렬 → 스크롤 → 저장 | O |
| `gmaps_rpc.py` | 가로챈 응답(JSON)에서 리뷰 필드를 뽑아 표 형태로 변환 | X |
| `test_google_extractors.py` | 위 두 파일의 파싱 로직이 맞는지 로컬 픽스처로 검사 | X |
| `google_login.py` | 크롬을 띄워 구글 로그인 세션을 프로필에 저장 (처음 한 번) | O |

## 2. 설치

### 사전 조건
- **Python 3.11 이상** (개발·검증 환경은 3.14, Windows 11)
- **데스크톱 크롬**이 설치되어 있어야 합니다. 스크립트가 `channel="chrome"`로
  실제 크롬을 띄우기 때문입니다.

### 설치 절차

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-google.txt
.venv\Scripts\python -m playwright install chromium
```

> macOS / Linux라면 `.venv/bin/python`으로 바꿔 읽으세요.
> 다만 실제 검증은 Windows에서만 했습니다.

## 3. 실행

> 처음 돌리는 것이라면 **[4. 실행 전 준비 두 가지](#4-실행-전-준비-두-가지)를 먼저 보세요.**
> 크롬 창을 닫아야 하고, 구글 로그인을 한 번 해두면 캡차가 훨씬 덜 뜹니다.

```bash
.venv\Scripts\python src/collect/google_reviews.py --target 임실치즈테마파크 --limit 100
```

크롬 창이 하나 뜨고, 리뷰 탭이 열리고, 리뷰 패널이 스크롤되는 모습이 보이면 정상입니다.
끝나면 `output/collect/google/` 폴더에 CSV와 XLSX가 같이 떨어집니다.

### 주요 옵션

| 옵션 | 설명 |
|---|---|
| `--target 이름` | `google_reviews.py`의 `TARGETS`에 등록된 관광지 하나만 수집 |
| `--all` | `TARGETS`에 등록된 전체 수집 |
| `--limit N` | 장소당 목표 리뷰 수 (기본 50) |
| `--resolve "장소명"` | 장소명으로 `feature_id`만 조회하고 종료 (신규 장소 등록용) |
| `--debug` | 어떤 셀렉터가 먹혔는지, 스크롤이 얼마나 내려갔는지 상세 출력 |
| `--dump` | 수집하지 않고 진단 스냅샷(스크린샷·HTML·셀렉터 매칭 수)만 저장 |
| `--save-raw` | 가로챈 RPC 원본 응답 앞 3개를 `.local/diagnostics/`에 저장 |
| `--no-hitl` | 캡차가 떠도 사람 개입 없이 그 장소를 건너뜀 |
| `--stall-limit N` | 새 리뷰가 안 나오는 스크롤이 N회 연속되면 종료 (기본 4) |

### 새 관광지 추가하기

`google_reviews.py` 상단의 `TARGETS` 리스트에 항목을 추가합니다.

```python
TARGETS = [
    {
        "name": "임실치즈테마파크",
        "feature_id": "0x356fd7ba9e08fc69:0x26115af9b51d3f84",
        "query": "임실치즈테마파크",
    },
]
```

- `feature_id`를 모르면 `"feature_id": None`으로 두고 `query`만 채워도 검색으로 진입합니다.
- 정확한 값을 미리 알아두는 편이 안정적입니다. 아래 명령으로 조회할 수 있습니다.

```bash
.venv\Scripts\python src/collect/google_reviews.py --resolve "옥정호 출렁다리" "임실 국사봉전망대"
```

## 4. 실행 전 준비 두 가지

### (1) 크롬 창을 전부 닫으세요 — 필수

크롬은 프로필 폴더 하나를 한 프로세스만 쓸 수 있습니다.
평소 쓰던 크롬이 켜져 있으면 스크립트가 프로필을 잡지 못하고
`프로필 잠금 파일이 남아 있습니다` 경고를 냅니다. 작업 표시줄에서 크롬을 완전히 종료하고 실행하세요.

### (2) 구글 로그인을 한 번 해두세요 — 권장 (2분, 처음 한 번만)

**왜 하나요?**
로그인 안 된 맨 브라우저로 구글 지도를 계속 긁으면 `"비정상적인 트래픽이 감지되었습니다"`
캡차가 뜹니다. 뜨면 수집이 멈추고 사람이 직접 풀어줘야 합니다.
로그인 세션이 한 번 자리 잡으면 이 빈도가 크게 줄어듭니다.

**안 하면 안 되나요?**
됩니다. 로그인 없이도 스크립트는 그냥 돌아갑니다. 한두 번 돌려볼 거면 건너뛰어도 됩니다.
여러 장소를 반복해서 돌릴 사람만 해두세요.

#### 방법 A — 스크립트로 로그인해두기 (이게 제일 쉽습니다)

```bash
.venv\Scripts\python src/collect/google_login.py
```

1. 크롬 창이 뜨고 구글 로그인 페이지가 열립니다.
2. **그 창에서** 평소처럼 본인 구글 계정으로 로그인합니다. (비밀번호는 본인이 직접 입력)
3. 로그인이 끝나면 터미널로 돌아와 **Enter**를 누릅니다. 창이 닫힙니다.
4. 끝입니다. 레포 최상위에 `.local/chrome_profile_google/` 폴더가 생기고 세션이 저장됩니다.
   이후 `google_reviews.py`는 자동으로 이 세션으로 접속합니다.

한 번만 하면 됩니다. 세션이 만료돼서 다시 캡차가 잦아지면 그때 한 번 더 돌리세요.

#### 방법 B — 평소 쓰는 크롬 프로필을 복사하기

이미 로그인돼 있는 본인 크롬 프로필을 통째로 가져오는 방법입니다.
방법 A로 충분하니 굳이 안 하셔도 되지만, 확실하게 하고 싶다면:

1. **크롬을 완전히 종료합니다.**
2. 탐색기 주소창에 아래를 그대로 붙여넣고 Enter — 크롬 프로필 폴더가 열립니다.
   ```
   %LOCALAPPDATA%\Google\Chrome\User Data
   ```
   (실제 경로는 `C:\Users\<사용자명>\AppData\Local\Google\Chrome\User Data`입니다.
   `AppData`는 숨김 폴더라 직접 찾아 들어가려면 보기 설정을 바꿔야 해서, 위 주소를 쓰는 게 빠릅니다.)
3. 그 안에서 **`Default` 폴더**와 **`Local State` 파일** 두 개만 복사합니다.
   폴더 전체는 2GB가 넘고, 나머지는 필요 없습니다.
4. 레포 최상위의 `.local/` 안에 `chrome_profile_google`이라는 폴더를 새로 만들고,
   복사한 두 개를 그 안에 붙여넣습니다. 결과가 이 모양이면 성공입니다.
   ```
   레포 최상위/
   └─ .local/
      └─ chrome_profile_google/
         ├─ Default/          ← 폴더
         └─ Local State       ← 파일
   ```
5. 용량이 크면 `Default` 안의 `Cache`, `Code Cache`, `Service Worker` 폴더는 지워도 됩니다.
   쿠키(=로그인 정보)는 `Default\Network\Cookies`에 있어서 그것만 남으면 됩니다.

### ⚠️ 이 프로필 폴더는 절대 공유하지 마세요

`chrome_profile_google/` 안에는 쿠키와 로그인 정보가 그대로 들어 있습니다.
이 폴더를 받은 사람은 **본인 구글 계정에 로그인된 상태로 브라우저를 열 수 있습니다.**
메신저로 보내거나, 압축해서 올리거나, git에 커밋하지 마세요.

- 그래서 레포에도 프로필이 빠져 있고, `.gitignore`에 `.local/`과 `chrome_profile_google/`을 넣어뒀습니다.
- 팀원마다 자기 PC에서 **방법 A를 한 번씩** 하면 됩니다. 그게 정상적인 사용법입니다.

## 5. 결과 파일 컬럼

| 컬럼 | 설명 |
|---|---|
| `관광지명` | `TARGETS`에 적은 이름 |
| `플랫폼` | 고정값 `구글` |
| `리뷰ID` | 구글이 부여한 리뷰 고유 ID. 중복 제거·재수집 대조의 키 |
| `작성자닉네임` / `작성자ID` / `작성자총리뷰수` | 작성자 정보 |
| `평점` | 1~5 |
| `작성일` | **절대 시각** (`YYYY-MM-DD HH:MM:SS`) |
| `수정일` | 리뷰를 고친 시각. 수정 이력이 없으면 작성일과 같음 |
| `수정여부` | 수정된 리뷰면 `수정` |
| `작성일_상대표기` | 화면에 보이는 `"3년 전"` 같은 표기 |
| `리뷰본문` | 잘리지 않은 전문 (줄바꿈 보존) |
| `본문길이` | 본문 글자 수 |
| `방문일` / `대기시간` / `예약권장` | 구글의 구조화 속성 (화면에서는 '자세히 보기'를 눌러야 보임) |
| `기타속성` | 위 3개 외의 속성을 `라벨=값|라벨=값` 형태로 보존 |
| `정렬기준` | `최신순` 또는 `기본(관련성순)` |
| `feature_id` | 장소 고유 식별자 |
| `수집시각` | 수집을 돌린 시각 |

### 분석 전에 반드시 알아둘 점

1. **구글의 '최신순'은 작성일이 아니라 수정일 기준입니다.**
   `작성일`과 `수정일`이 크게 벌어진 행은 오래전 리뷰를 최근에 고친 경우입니다.
   시계열 분석에서 어느 쪽을 쓸지 팀에서 먼저 정하고 시작하세요.
2. **별점만 있고 본문이 없는 리뷰도 수집됩니다.** 이것도 유효한 데이터라 일부러 남겼습니다.
   텍스트 분석을 할 때는 `본문길이 > 0`으로 걸러 쓰세요.
3. CSV는 `utf-8-sig`로 저장하므로 엑셀에서 바로 열어도 한글이 깨지지 않습니다.

## 7. 문제가 생겼을 때

### 먼저 이 테스트부터 돌려보세요

```bash
.venv\Scripts\python src/collect/test_google_extractors.py
```

구글에 접속하지 않고 로컬 픽스처만으로 파싱 로직을 검사합니다.
수집 실패의 원인은 보통 둘 중 하나인데,

- **(가) 구글이 화면 구조를 바꿔서 셀렉터가 안 맞음**
- **(나) 파싱 코드 자체가 틀림**

이 테스트가 통과하면 (나)가 배제되므로 남은 건 (가)입니다.

### (가)라면 — 진단 스냅샷을 뜨세요

```bash
.venv\Scripts\python src/collect/google_reviews.py --target 임실치즈테마파크 --dump
```

`.local/diagnostics/` 폴더에 스크린샷·페이지 HTML·리뷰 카드 HTML과 함께
"어떤 셀렉터가 몇 개 매칭됐는지"가 담긴 `_probe.json`이 떨어집니다.
그걸 보고 `google_reviews.py` 상단의 `SEL_*` 폴백 체인만 고치면 됩니다.
추측으로 고치지 말고 실제 DOM을 보고 고치는 게 훨씬 빠릅니다.

### 자주 만나는 증상

| 증상 | 원인 / 대처 |
|---|---|
| `프로필 잠금 파일이 남아 있습니다` 경고 | 크롬이 켜져 있습니다. 전부 닫고 다시 실행 |
| 캡차 / "비정상적인 트래픽" 화면 | 스크립트가 감지해서 멈추고 대기합니다. 뜬 크롬 창에서 직접 통과시킨 뒤 터미널에서 Enter. 자꾸 뜨면 `google_login.py`를 한 번 돌려 로그인 세션을 만들어두세요 (4절) |
| `RPC 응답을 한 건도 잡지 못했습니다` 경고 | 구글이 응답 형식을 바꿨을 수 있습니다. DOM 폴백으로 수집은 계속되지만 컬럼이 줄어듭니다 (`작성일` 절대 시각, 작성자 ID, 구조화 속성이 빠짐) |
| 목표 건수보다 적게 수집됨 | 그 장소에 실제로 있는 리뷰가 그만큼인 경우가 대부분입니다. 로그의 `종료:` 사유를 확인하세요 |
| `리뷰 탭을 찾지 못했습니다` | 장소 페이지가 아니라 검색 결과 목록에 머물러 있을 수 있습니다. `--resolve`로 `feature_id`를 확정해 `TARGETS`에 넣으세요 |

## 8. 수집할 때 지켜주세요

- **`--headless`는 쓰지 마세요.** 옵션은 있지만 탐지 위험이 크게 올라갑니다.
- 여러 장소를 연속으로 돌릴 때 스크립트가 장소 사이에 8초 내외를 쉽니다. 이 간격을 줄이지 마세요.
  연속 요청은 IP 신뢰 점수를 떨어뜨려 결국 전체가 막힙니다.
